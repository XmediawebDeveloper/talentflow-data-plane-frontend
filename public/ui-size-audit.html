00Key findings & recommended sizes

The short version of everything on this page. The standards below are now global classes in app/globals.css (see section 13), and the fixes marked Fixed are applied in the code.

What I found

  • Buttons: heights of 24, 28, 32, 36, 38, 40 and 44px are all in use. The shared button token is 36px but <Button size="md"> is 40px.
  • Inputs: 36px, 38px and 42px were mixed. Fixed: all hand-written fields and the 38px toggles beside them are now 36px.
  • 13px text on phones: 278 uses in the Organization module. Fixed: removed, so phones show 14px like the JD module.
  • Off-scale text: 11px, 10px, 9px, 13px, 14px written by hand. Fixed: mapped to text-xs, text-2xs, text-sm.
  • Switch: turned grey when on. Fixed: brand blue, like checkboxes.
  • Focus ring: buttons grey, inputs blue. Fixed: one brand-blue ring.
  • Radio buttons: the shared RadioGroup component is never used; all radios are hand-built.
  • Components: 711 <Button> vs 2,016 raw <button>; 48 <Input> vs 418 raw <input>.

Recommended sizes (all devices)

  • Font: Inter only. Page title 18px phone → 20px from 640px. Card title 16px. Body, inputs, tabs, buttons 14px everywhere. Meta 12px. Micro 10px only in dense tables.
  • Buttons: <Button> md 40px default (full width in phone modal footers), sm 32px for rows and toolbars, lg 44px for login and candidate pages.
  • Inputs / selects / search / date: 36px (h-9), the size every shared form component already uses.
  • Tabs: pill tabs on list pages (32px), underline tabs on detail pages (job-details pattern).
  • Radio / checkbox: 16px on every screen, inside a clickable label.
  • Colors: brand blue #0f3c99 for every CTA, active and focus state; gray for light, slate for dark.
  • Radius: 8px controls, 12px cards, 16px modals, full for pills.
  • Spacing: page padding 16px phone, 24px from 640px, 32px from 1536px. Card padding 16 → 20px.
  • Breakpoints (global only): 2xs 360 · xs 400 · sm 640 · md 768 · lg 1024 (sidebar appears) · xl 1280 · 2xl 1536. Test at 320px first.

01Summary

The project already has a written standard: the type scale comment in globals.css, components/ui/design-tokens.ts, and the <Button> component with three variants. Most screens follow it. The drift is in hand-written markup that doesn't use the shared components.

Already consistent

  • One font family (Inter) and two main text sizes: 14px (text-sm, 5,444 uses) and 12px (text-xs, 4,460).
  • Brand blue #0f3c99 is the single CTA and active color (2,224 bg-brand-blue).
  • 8px radius (rounded-lg) is the default for controls: 3,094 uses.
  • Modals share one shell (AppModal) with a full-screen sheet on phones.

Where it drifts

  • Button heights: 24, 28, 32, 36, 38, 40 and 44px are all in use. tokens.buttonPrimary is 36px while <Button size="md"> is 40px.
  • Input heights: 36px (<Input>), 38px (raw py-2), 42px (raw py-2.5). Fixed to 36px.
  • 13px text on phones (max-sm:text-[13px], 278 uses) in the Organization module. Fixed to 14px.
  • Focus ring: <Button> grey, inputs blue. Fixed to one brand-blue ring.
  • Zero uses of the shared RadioGroup; radios are native. Use tf-radio.

Rule

  • gray scale for light theme, slate for dark theme (that's how design-tokens.ts pairs them). Keep it.
  • Text: gray-900 heading · gray-700 body · gray-600 muted · gray-500 subtle. Don't use gray-400 for readable text (fails 4.5:1 on white).
  • Only brand-blue is "action". Cyan/teal/orange are accents for icons and charts, not buttons.

Drift

  • Raw Tailwind hues used beside the semantic tokens: text-red-600 185, text-blue-600 119, bg-emerald-500 61, indigo / purple / violet ~200 combined.
  • ~40 distinct hex literals in .tsx (e.g. #7c3aed, #e11d48, #0891b2). Map them to the tokens above.

Responsive rule for tabs

  • List pages use pill tabs (A); detail pages use underline tabs (C); segmented (B) only for 2–4 view switches inside a card.

10Breakpoints in use

The 33 hand-written widths in components were converted, and the raw @media (…px) rules in globals.css now read theme(--breakpoint-*).
